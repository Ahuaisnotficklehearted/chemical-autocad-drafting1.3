# 控制方案与回路骨架（P&ID 局部回路速查）

> **来源**：知识库 `01-PID与流程图标准/PID制图与控制方案速查.md`、`06-自控与图纸沉淀/控制方案附图画法规范.md`、
> `06-自控与图纸沉淀/整套P&ID控制方法沉淀.md`（三份均已通读消化）。
> **用途**：把「工艺上要控制什么」翻译成「图上画什么」，并给出**可直接粘进规格**的 `loops` 片段。
> **引擎侧**闭环校验见 `drawing-engine.md` §8；规范条文依据见 `drawing-conventions.md`。

---

## 一、整套 P&ID 的阅读顺序（不要孤立看仪表）

```text
首页/图例/图框 → 设备位号与管线编号 → 主物料线和流向 → 设备/管口/阀门/管件
→ 仪表和测点 → 仪表连接线 → 电动/气动信号线 → 控制器/功能块
→ 调节阀/执行机构 → 流股接续和跨图接口 → 报警、联锁、公用工程和特殊说明
```

**核心原则**：沿「被控对象 → 测量点 → 控制器 → 输出 → 最终控制元件」**闭合追踪**。
只看一个孤立仪表就下结论，是最常见的误判来源——因为一个仪表圆可能属于串级副回路、
前馈通道或多冲量的一路，含义完全不同。

> **为什么先说阅读顺序**：绘图与审图是同一枚硬币的两面。你按什么顺序读图，
> 就决定了你按什么顺序写规格——`draw_pfd.py` 的「顺序即依赖」正是这条阅读链的代码化。

## 二、控制回路通用骨架（6 类）

| 类型 | 骨架 | 画图要点 | 引擎 `loop_type` |
|---|---|---|---|
| **单回路反馈** | 对象 → 测量/变送 → 控制器 → 输出 → 执行机构 → 操纵变量 | 最基本闭环，五要素缺一不可 | `single` |
| **串级** | 主测量 → 主控制器 → **副回路设定值** → 副控制器 → 执行机构 | 副测量点必须**实际落在**副变量管线/设备上，不能只画两个控制框 | `cascade` |
| **前馈-反馈** | 扰动测量点 + 被控变量反馈点 → 前馈/反馈功能块 → 共同输出 | 两条取信号路径都要画出；扰动点与反馈点**都不重合** | `feedforward` |
| **分程** | 一个控制器输出 → 分程功能块 → 两只不同范围/介质的阀 | 两个执行端分别落在**实际管线**上 | `split` |
| **多冲量** | 每个冲量有独立测量点 + 独立信号线 → 汇入功能块 | 锅炉三冲量至少含**液位、蒸汽流量、给水流量** | `multi_impulse` |
| **旁路** | 旁路线 + 旁路阀 + 回到明确节点 + 流向箭头 | 必须是**真实管线**，不是装饰线 | 见 §5.7（非独立类型） |

**旁路不是一种 `loop_type`**——引擎支持的五种回路类型里没有 `bypass`。
旁路的本质是「**一根真实旁路管 + 其上一只调节阀**」，再加一条以该阀为 `final_element`
的 `single` 回路。这一区分很重要：把旁路当成一种回路类型去"画"，而不去画那根管子，
就会得到一条悬空的装饰线——正是 `控制方案附图画法规范.md` 明令禁止的失败模式。

## 三、11 类典型设备的控制方案

| 设备 | 常见操纵端 | 图面注意事项 |
|---|---|---|
| **离心泵** | 出口流量/压力、出口旁路、变速 | 控制阀画**出口**，**吸入口不放**普通流量阀 |
| **往复泵** | 转速、冲程、出口旁路 | **不可照搬**离心泵出口节流逻辑 |
| **压缩机** | 入口阀、旁路回流、转速 | 离心机须表达**防喘振回路**；旁路闭合回入口侧 |
| **换热器** | 载热体/冷却剂流量、凝液 | 单回路 `TT→TIC→TV`；串级时主副测点/信号线分开 |
| **锅炉汽包** | 液位/蒸汽流量/给水流量 | 单/双/三冲量测点分别画齐 |
| **燃烧过程** | 燃料、空气流量 | 燃料/空气/烟气/蒸汽流程分开，信号线不与物料线混淆 |
| **精馏塔** | 回流阀、蒸汽阀、凝液阀 | 塔+冷凝器+回流+再沸器+进料+顶底产品**先画完整**；双温差保留两支测量 |
| **釜式反应器** | 冷/热剂流量、夹套温度、釜压 | 串级画反应温度主测点 + 夹套副测点 |
| **固定床反应器** | 进料浓度/温度、载热体、段间冷气、旁路 | 多段床层要画**段间接口和冷气阀**，不能压成一个矩形 |
| **流化床反应器** | 入口温度、冷剂流量 | 差压系统须有**上下两个取压点** + 差压变送，不能只画一个压力表 |
| **发酵罐** | 温度、pH、溶氧、罐压、泡沫 | 按功能分组：罐体/搅拌/通气/冷却/酸碱/消泡；加料泵落在实际加料管线 |

### 3.1 逐类落地要点（与符号库锚点的对应）

- **离心泵**：出口流量反馈 `FT→FIC→出口 FV`。确认设备型式后使用 `pump.centrifugal` 图块，图面连接点为 `inlet`/`outlet`；
  调节阀挂在出口管线上（`valves` 里 `on:"PL-…"`）。
- **压缩机**：先确认型式与对应图库块；防喘振旁路的实际接口由项目资料确定，图库边界连接点不代表实体管口。
- **换热器/再沸器**：`exchanger` 锚点 `shell_in`/`shell_out`/`tube_in`/`tube_out`；
  釜式重沸器 `kettle` 另有 `vapor`（汽化返回塔的上升管）。
- **精馏塔**：先识别板式、填料等型式并调用对应块；回流、塔顶、再沸器支路的实体接口须按项目资料确认。
- **流化床差压**：上下取压点必须来自项目接口资料，再接差压变送器；不能用一个普通压力表替代。
- **储气罐/受压设备**：确认对应图块及安全阀实际接口，再引出安全阀并注 `inlet_note`。

## 四、理论对象 → 图面对象（强制映射）

| 理论对象 | P&ID 图面对象 | 引擎里的载体 |
|---|---|---|
| 被控对象 | 设备、管段、换热面、工艺空间 | `equipment`（含锚点）/ `pipes` |
| 被控变量 | 温度、压力、流量、液位、pH、溶氧、差压 | 回路 `variable` 首字母 `T/P/F/L/A` |
| 测量元件 | 仪表圆、变送器、取压/取温点 | `measurement_point`（引用，须落在几何上） |
| 控制器 | 控制仪表块、功能框、控制室表示 | `controller_tag` + `controller_at` |
| 操纵变量 | 载热体、冷剂、给水、燃料、空气、回流、旁路 | 管线 + 其上的调节阀 |
| 最终控制元件 | 调节阀、执行机构、变速器、加料泵、电机接口 | `final_element`（须是 `is_final_element` 的阀） |
| 控制信号 | 电动/气动信号线（**独立于工艺物料线**） | `SIGNAL` 图层，由回路自动生成 |
| 跨图关系 | 流股接续、管线号、控制室/仪表盘接口 | `offpage` 接续符 |

> **这张表是"翻译词表"**：工艺专业说"要控釜温"，图上必须依次落到
> 设备 → 测点 → 控制器 → 阀 → 信号线五个实体上。缺任何一个，翻译就不完整。

## 五、回路 → 规格 `loops` 片段（可直接粘贴）

### 5.1 字段表（与 `chemcad_engine.ControlLoop` 一一对应）

| 字段 | 必填 | 说明 |
|---|---|---|
| `loop_id` | ✅ | 回路标识，如 `T-201`（校验与报错用它定位） |
| `variable` | ✅ | 被测变量首字母：`F/L/T/P/A`…（须与位号首字母一致） |
| `number` | ✅ | 回路序号，如 `"101"`（同回路所有元件共享） |
| `controlled_object` | ✅ | 被控对象（设备/管线 id） |
| `measurement_point` | ✅ | 测量点引用，**须落在被控对象几何上** |
| `controller_tag` | ○ | 省略时默认 `{variable}IC{number}`，如 `FIC101` |
| `final_element` | ○ | 最终元件位号，省略时默认 `{variable}V{number}`，如 `FV101` |
| `loop_type` | ○ | `single`（默认）/`cascade`/`feedforward`/`split`/`multi_impulse` |
| `sub_measurement` | 串级必填 | 副测量点，**须落在副变量管线/设备上**，且不得与主测量点重合 |
| `sub_controller_tag` | ○ | 副控制器位号，省略时默认 `{variable}C{number}B` |
| `extra_measurements` | 前馈/多冲量必填 | 额外测量点列表（前馈≥1，多冲量≥2） |
| `extra_finals` | 分程必填 | 第二只（及以后）执行阀位号列表（分程≥1） |
| `controller_at` | ○ | 主控制器气泡坐标；省略时自动放在测量点右上 30/34 |
| `sub_controller_at` | ○ | 副控制器气泡坐标；省略时自动放在副测量点右下 30/−34 |

> `measurement_point` / `sub_measurement` / `extra_measurements` 都用**统一引用语法**：
> `"T-101.top"`（设备+锚点）｜`"PL-FEED@0.70"`（管线上累计长度比例取点）｜`"123.5,300"`（字面坐标）。

### 5.2 单回路（`single`）

```json
{ "loop_id": "F-101", "variable": "F", "number": "101",
  "controlled_object": "T-101",
  "measurement_point": "PL-FEED@0.70",
  "controller_tag": "FIC101", "final_element": "FV101",
  "loop_type": "single",
  "controller_at": [112, 460] }
```

### 5.3 串级（`cascade`）——主测量控釜温、副回路控蒸汽流量

```json
{ "loop_id": "T-201", "variable": "T", "number": "201",
  "controlled_object": "T-201",
  "measurement_point": "T-201.bottom",
  "controller_tag": "TIC201", "final_element": "TV201",
  "loop_type": "cascade",
  "sub_measurement": "PL-STM@0.50",
  "sub_controller_tag": "FIC201B",
  "controller_at": [180, 250], "sub_controller_at": [345, 235] }
```

> ⚠️ 副测量点 `PL-STM@0.50` **必须真的落在蒸汽管线上**——校验器会逐条核对；
> 只给两个控制框、副测点飘在空中，`validate_control_loops()` 直接报错。

### 5.4 前馈-反馈（`feedforward`）——加热炉出口温度 + 进料量扰动前馈

```json
{ "loop_id": "T-301", "variable": "T", "number": "301",
  "controlled_object": "F-301",
  "measurement_point": "PL-OUT@0.60",
  "controller_tag": "TIC301", "final_element": "TV301",
  "loop_type": "feedforward",
  "extra_measurements": ["PL-FEED@0.20"],
  "controller_at": [200, 400] }
```

> 两条取信号路径都要画：被控量反馈（`measurement_point`）+ 扰动前馈（`extra_measurements`）。

### 5.5 分程（`split`）——一只控制器分程驱动两只阀

```json
{ "loop_id": "P-401", "variable": "P", "number": "401",
  "controlled_object": "V-401",
  "measurement_point": "V-401.top",
  "controller_tag": "PIC401", "final_element": "PV401A",
  "loop_type": "split",
  "extra_finals": ["PV401B"],
  "controller_at": [300, 520] }
```

> 两个执行端（`PV401A`/`PV401B`）**都要先作为 `valves` 落在实际管线上**，否则引擎找不到它们、
> 报 `分程回路最终元件不足`。

### 5.6 多冲量（`multi_impulse`）——锅炉汽包三冲量

```json
{ "loop_id": "L-501", "variable": "L", "number": "501",
  "controlled_object": "DRUM-1",
  "measurement_point": "DRUM-1.bottom",
  "controller_tag": "LIC501", "final_element": "LV501",
  "loop_type": "multi_impulse",
  "extra_measurements": ["PL-STM@0.30", "PL-FW@0.50"],
  "controller_at": [260, 480] }
```

> 三冲量 = 液位（`measurement_point`）+ 蒸汽流量 + 给水流量（两个 `extra_measurements`）。
> 校验要求 `extra_measurements` **≥ 2**，即独立测量点至少三个。

### 5.7 旁路（用 `pipes` + `valves` + `single` 回路表达）

旁路**没有独立 `loop_type`**。正确做法是三件事一起做：

```json
// ① 画一根真实旁路管（必须正交、必须回到明确节点）
{ "id": "PL-BYP", "from": "P-101.discharge", "to": "T-101.feed",
  "layer": "PIPE_INLINE", "dn": 50, "arrows": true },

// ② 旁路管上挂一只调节阀（它才是执行端）
{ "tag": "FV101B", "type": "control", "on": "PL-BYP", "t": 0.5,
  "params": { "actuation": "气动", "action": "气关", "manual": false } },

// ③ 一条 single 回路，把该阀作为 final_element
{ "loop_id": "F-101B", "variable": "F", "number": "101B",
  "controlled_object": "P-101",
  "measurement_point": "PL-DISCH@0.40",
  "controller_tag": "FIC101", "final_element": "FV101B",
  "loop_type": "single" }
```

> 泵最小流量保护、压缩机防喘振、换热器切旁路，都是这套模板。

## 六、验收清单与失败模式红线

### 6.1 验收清单

- [ ] 先确定**设备类型**和**控制方案类型**
- [ ] 工艺对象和完整物料路径已画出（**真实流程**，非脱离流程的装饰几何）
- [ ] 能从检测点**沿信号线追到控制器**、再**沿输出线追到最终元件**（追索路径完整）
- [ ] 测量点位于**实际测量位置**（落在几何上，不飘空）
- [ ] 控制器、执行机构、最终控制元件**三者齐备**
- [ ] 执行机构与阀门画在**合理的工艺位置**
- [ ] 所有线逐段水平/竖直（**禁止斜线**）
- [ ] 串级/前馈/分程/多冲量**没被压扁成单回路**
- [ ] 副测量点独立取信号、不与主测量点重合
- [ ] 仪表位号、回路标识、**流向可读**
- [ ] **无线条穿过**文字、设备轮廓或不应连接的节点
- [ ] 图层符合所用分类体系（语义命名优先）
- [ ] 泵、阀门、仪表优先复用符号库块或经确认的图例
- [ ] 图纸名称、版本、实体数量、截图已复核（**实体查询 + 截图 + 保存文件三重确认**）

### 6.2 失败模式红线 🚫

> **只有设备外形 + 一个仪表圆 + 若干装饰线 ＝ 工艺示意，不是控制方案附图。**

其它明令禁止：

1. 用斜线连接检测点与控制器；
2. 用抽象方框代替实际设备/管道对象；
3. 只做视觉相似，不表达控制逻辑闭环（无"检测点→控制器→执行端"的追索路径）；
4. 不读样本图层与块定义，直接按通用 CAD 习惯猜符号；
5. 打开图纸后未核验当前图名/路径就开画（可能仍在原图上操作）。

## 七、线与布局细则（画完必查）

来源：`控制方案附图画法规范.md` §线与布局。这几条是「能出图」与「图能看」的分界线：

| 规则 | 说明 |
|---|---|
| **一律正交** | 物料线、控制线、仪表连接线默认水平/竖直；**禁止为省事用斜线** |
| **分层可读** | 物料线、信号线、公用工程线层次分明，**不让信号线与主流程线混淆** |
| **回路按序排布** | 按「测量点 → 变送器 → 控制器/功能框 → 输出线 → 执行机构/阀门」顺序布置 |
| **控制器靠中** | 控制器/功能框宜放在**信号路径中部**，不能离执行端过远导致回路关系靠猜 |
| **不缩字掩盖问题** | 位号/文字避免压线、重叠、遮挡轮廓；**线不够长就调布局，不缩小文字** |
| **多回路成组** | 按温度/压力/流量/液位/分析分组，同图内**符号尺寸与线型保持一致** |

> 引擎已把前两条变成硬约束（`ortho_path` + `validate_orthogonality`、图层注册表）；
> 后四条属「版面/可读性」，**自动校核查不出**，只能靠 `preview_dxf.py` 出图目视——
> 这正是 `references/experience-base.md` 反复强调「自动校核查不出丑」的原因。

## 八、与引擎的衔接：闭环"画不出来即不闭合"

本技能的出图引擎把上面这套验收规则**变成了代码约束**（详见 `drawing-engine.md` §8）：

| 规则 | 引擎保证 |
|---|---|
| 五要素齐备 | `validate_control_loops()` 逐条核对被控对象/测量点/控制器/最终元件 |
| 测量点真落在几何上 | 用 `GeometryIndex` 按点—线段距离判定，**飘空即报错** |
| 同回路共享序号 | 核对位号首字母 = 被测变量，且序号一致 |
| 最终元件是阀且落在管线上 | 核对 `is_final_element` 且几何在管线上 |
| 串级副测点必填且独立 | 缺 `sub_measurement` → 报错；与主测点重合 → 报错 |
| 前馈须给扰动测点 | `extra_measurements` 为空 → 报错 |
| 分程须 ≥ 2 只阀 | `extra_finals` 为空 → 报错 |
| 多冲量须 ≥ 2 独立测点 | `extra_measurements < 2` → 报错 |
| 信号线接执行机构而非阀体 | `wire_loop()` 优先接 `actuator` 锚点，避开物料管线 |

**结论**：回路定义**同时是数据源与绘图源**——信号线由它生成，
所以「闭环可追踪」不是事后检查出来的，而是**画不出来不闭合**。
