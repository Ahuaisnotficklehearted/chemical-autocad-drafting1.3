## 一、六条进化铁律（照做，不要省）

- 每解决一个问题，用 Edit 在 §四「动态经验记录」追加一条：
  `[日期] 一句话摘要 / 需求类型 / 采用方案 / 结果 / 经验`。

- 按用户/开发者授权运行当前回归与 `--check-only`，再检查实际图。旧selftest包含已禁止的直接COM简化原生块行为，不能作为新版通过证明。

- 交付时若存在更省事/更规范/更不易返工的现成办法，用「💡 还能更好」顺带提出，不强迫、不啰嗦。

### 6. 自我对账（文档 ↔ 代码 ↔ 资产，三方谁都不许单独改）

**铁律**：凡是你**写下的结论**（文档里的数字/清单/映射/尺寸）与**你改过的代码或资产**，
交付前必须**互相验证一遍**——不信自己的记忆，也不信自己上一步写的字面。

**为什么单列一条**：本技能最贵的错误不是「崩」，是**静默失真**——
断言全绿、图也画得出来，但**内容是错的**。这类错误**只有靠对账才抓得到**，靠回归抓不到。
实测血泪（2026-09-29 一天内三连）：

| 失真类型 | 实例 | 为何断言没拦住 |
|---|---|---|
| **文档抄错** | `equipment-library.md` 全表 7 处尺寸凭印象写（`hx.shell_tube` 写 24×72、实为 26×26） | `[24]` 只查"符号能解析"，查不到"文档写的数对不对" |
| **契约未钉死** | 14 个老符号只注册中文名，规格写 `hx.shell_tube` **静默解析不到** | 原断言写的是"id **或**中文名任一登记"——过宽，放过了缺口 |
| **口径不一致** | 拿"含接管的包围盒"去比 catalog 的"本体 size"，误判 33 项尺寸错 | 测量方法本身没核对，得出的"证据"是假的 |

**所以每次交付前，逐条过一遍**：

1. **文档里的数 → 去源文件核**：文档写的尺寸/计数/清单，必须能在 `catalog.json`、
   `LAYER_REGISTRY`、`selftest.py` 等**单一事实来源**里查到；查不到就改文档。
2. **代码里的映射 → 去权威源核**：`MOD_TO_TYPE`、`EQUIPMENT`、`LAYER_REGISTRY` 这类表，
   逐项对权威源（图库 catalog / Excel 表 / HG 标准原文），不靠印象补。
3. **能量化的对账 → 变成断言**：数字修一次就完了，**断言会在下次漂移时喊停**。
   例：`[24]` 新增「选型文档 §2 全表 == catalog（id 集合 + 尺寸列）」。
4. **口径先对齐，再下结论**：比较两个量之前，先确认它们**测的是同一件事**
   （本体 vs 含接管？含法兰 vs 不含？中心 vs 左下角？）。口径没对齐就下的结论＝假的。
5. **别改别人要用的东西**：清理/删除前，先 `grep` 谁引用了它——用户点名要删的，
   也可能是 `selftest.py` 的默认夹具（实测 `DEFAULT_SPEC` 就是被点名的那份示例）。
6. **删一个东西前，先查它有几个载体**：用户说"这个也一并处理"时，要问的是
   **"它有几份副本、分别在哪"**，不是"删掉手上这份就完事"。载体常跨**三个层次**：
   ① 技能目录内 ② 技能目录外的**用户资产**（如工作区 `知识库/`——技能里的
   `references/*.md` 往往只是它的**二次蒸馏**）③ 会话/工作区记忆。
   - ⚠️ **同名陷阱**：出现同名词**不等于**同一份东西——中文工程名词尤甚（实测 `grep` 一个词
     会命中教材正文里的同名字段）。**必须读上下文**确认是同一实体，否则会误删别人的资料。
   - **边界**：`知识库/` 是**用户自己的资产**，技能只引用、**不拥有**——
     清技能时**不动知识库本体**（除非用户明确指定路径并要求），技能侧只**撤掉引用**。
   - **不留痕（用户偏好）**：清理后**不写**"××已移出""2026-xx-xx 更新"这类带日期的变更叙事，
     技能文档保持干净，只留**功能性范围声明**（如"只出 PFD"）。
   - 完整删除流程见 skill **`cleanup-task-protocol`**。

**一句话**：**凡是我写下的，都要能被别人的工具重新算出来一遍。**

## 二、四大高频场景与最优方案（按实际频率排序）

### 1. 出图（最高频）★
- **定义**：从工艺方案生成一张规范 P&ID/PFD。
- **最优路径**：写 JSON 规格 → `python scripts/draw_pfd.py spec.json --check-only` → 出图。
- **后端选择**：

  | 后端 | 何时用 | 命令 |
  |---|---|---|
  | `dxf`（默认） | 绝大多数情况；无需 AutoCAD | `--out pfd.dxf`（ezdxf/R2010，真线宽 370） |
  | `--no-ezdxf` | 没装 ezdxf / 要最老兼容 | 内置 R12 书写器，零依赖 |
  | `com` | 直接画进**运行中的** AutoCAD | `--backend com`（先开 CAD；`--create` 才允许自动启动） |
  | `scr` | 生成命令行脚本，在 CAD 里 `SCRIPT` 跑 | `--backend scr --out x.scr` |
  | `lisp` | 生成 `entmake` 脚本，含**真图块** | `--backend lisp --out x.lsp`（`APPLOAD` 后输命令名） |

- **关键点**：连接一律用**锚点或管线取点**（`"T-101.top"` / `"PL-FEED@0.35"`），**禁写魔数坐标**；
  P&ID 用「图纸尺寸」作图（1 单位 = 1 mm，文字高直接 2~3 mm），不是画小了。

### 2. 校核（评审已有 DXF）
- **最优路径**：`check_dxf.py`（含正交性）→ `preview_dxf.py` 出 PNG 目视。
- 机械图必须加 `--no-ortho`（30°/45° 剖面线是规范画法，不是违规）。
- **关键点**：自动校核查不出「丑」——文字压线、符号相撞、管路穿设备**只能靠目视**。

### 3. 读图提取（从 DWG/DXF/bkp 反推）★
- **落盘文件（首选，零依赖）**：`scripts/chemcad_locate.py`（详见 `references/locate-and-extract.md`）
  - `scopes 图.dxf` → 作用域切分 + **同名撞车自查**（**取对象前必须先跑**）
  - `locate 图.dxf --tag T-101` → 按位号定位（返回坐标 + bbox）
  - `pick 图.dxf --at 120,85` → 点拾取："这个坐标上是哪个对象"
  - `distance 图.dxf --a T-101 --b E-102` → 中心距 + **包围盒净距**（净距 0 = 相撞）
  - `texts 图.dxf --order column` → 提文字并还原图纸**分栏**阅读顺序
  - `bkp 案例.bkp --json case.json` → Aspen `.bkp` 的模块定位 + 流股拓扑 + **工艺结果**
- **轻量罗列**：`inspect_dxf.py <file> --json out.json`（图层/块/实体/文字）。
- **运行中的 AutoCAD**：`read_dwg.py --list-docs` / `--doc <关键词>` / `--layer <名> [--json]`
  （走 `ChemComReader`，读回图层表并与 `LW_RANGES` 对照线宽）。
- **关键点**：
  ① **先切作用域再取对象**——同名对象可能同时在模型空间与块定义里，一个 bkp 可能存多页 PFD；
  ② 读取一律走 `read_text_robust` 逐级降级，**禁用 `errors="replace"`**（静默失真）；
  ③ 块的**有效名**（动态块）要取 `EffectiveName`，不是块表里的 `Name`；
  ④ MText 要剥掉两层伪装（`\U+XXXX` 转义 + `\f…\`/`\C3;`/`%%d`… 格式码）才是真文字；
  ⑤ 解析不出来的进 `unresolved` 列出来，**不留空、不编造**；
  ⑥ **不越界找东西**——PFD/P&ID **不含管径与设备规格**（分别属管线表、设备数据表），
  取不到属预期，**不算缺失、不进 `unresolved`、不追问用户**（机械图相反，仍需设备规格）。

### 4. 知识消化（把本地标准/笔记变成可执行约束）
- **最优路径**：读知识库原件 → 蒸馏成 `references/*.md` → 能校核的写成**校验器** + `selftest.py` 用例。
- **关键点**：**区分证据强度**——有全文的标准可直接引用；扫描件标「⚠️ 待核原件」，
  绝不把 OCR 猜测当条款；范围类/介质类代号**以项目首页图为准**。

### [2026-09-30] 设备分配去启发式：**台数是猜的，包络才是真的**

- 问题：`split_spec` 用 `MAX_SHEET = 12`（"一张图最多 12 台"）+ `_neighbors_of` 投票 +
  `_cluster_of` 坐标网格聚类（魔数 `step=12.0`）决定分张——三处都是**猜**。
- 修法：① 容量改由 `_fit_count` 按**真实符号包络 + 图幅可用区**折行装填**算出**
  （复用 `chemcad_layout.measure_equipment / available_area / planning_area`，不建第二份尺寸表）；
  ② 无编号设备归段改**流股图 BFS**（跳数最少 → 同跳取位号字典序最小），结果唯一可复现。
- 教训：**别拿"个数"当容量**。一台塔 24×120、一台泵 11×11，同幅面差一个数量级；
  用台数阈值分张必然切错。任何"每页最多 N 个"的阈值，都该先问一句：**N 是从哪来的？**
- 副作用（有意保留）：尾组 <6 台并回上一组会让该组略超容量——两个约束在尾数小时无解，
  取用户硬约束优先。上限 = `cap + MIN_SHEET - 1`。

### [2026-09-22] 从 Aspen Plus .bkp 自动出全厂 PFD/P&ID（175 模块 / 241 流股）
- 需求类型：出图（大规模）
- 采用方案：① `.bkp` 是 GBK 文本，正则抓 `BLOCK BLKID=… BLKTYPE=… IN=(…) OUT=(…)` 得拓扑；
  ② 工段按位号数字前缀分组，工段名用 bkp 内嵌的中文框图标注（`[\u4e00-\u9fff]` 扫描）坐实；
  ③ 蛇形版面：DFS 先序保链连续 → 行内左右往返 → 每行行间走廊错层走线；
  ④ 符号**自适应缩放**（按每行可用高 / 每列可用宽搜索最优列距）；⑤ >45 台的工段沿
  「穿越流股最少」的拓扑切口拆成 A/B 两张；⑥ PFD 与 P&ID 同源，P&ID 增量补阀/仪表/回路
- 结果：成功（13 张图全过自检：正交 / 线宽 / 位号 / 闭环 / 文字高度）
- 经验：① **现场信息藏在文件里**——工段中文名、项目名、产品规格全在 bkp 的框图标注里，
  扫一遍 CJK 就有，不必凭空命名；② **本机没装 Aspen 也能出图**，.bkp 文本层就够出拓扑图；
  ⚠️ **原记录写"流股结果（T/P/F）不在里面"不准确**——`DSET STREAM … RES_STR` 段**带**
  温度/压力/质量流量/体积流量/摩尔流量/气相分率（见下条经验与 `chemcad_locate.parse_bkp_stream_results`）；
  而**管径与设备规格不在 bkp 里属预期之内，不算缺失**：PFD/P&ID 的图面内容本就不含这两项
  （管径属管道布置图 / 管道特性表，设备规格属设备数据表），
  **不要去识别、不要当缺失报出、不要编造**；
  ③ 自动布线查不出"丑"，每张都要 `preview_dxf.py` 出 PNG 目视过一遍再交付。
  ④ **一个 bkp 可能存多页 PFD**（顶层 + 层级块各一页）——按名找流股会撞车，
  必须先切作用域（见下条经验）。

     同理"管线穿设备"也要先让开管口 6 mm——管口本来就插进设备体内。
  ③ **迭代修正要"就地评过再选"，不能盲踏步进**。第一版让阀门沿管线每次挪 0.06，
     结果"挪一步撞上邻居、再挪又撞回来"，缺陷总数在 36~44 之间反复震荡；
     改成**直接算挪过去之后的包围盒**（沿管平移 + 竖管上长宽互换）跟所有符号比一遍、
     取净距最大者，一轮就到位。**同一条管线的走线决策也必须按管线聚合**，
     否则两次决策互相覆盖，`pipe_through` 在 5/8 之间反复跳。
  ④ **绝对坐标的"坐标系"必须钉死**。`fit_to_sheet` 在末尾整体平移居中，而 `repair_*`
     读到的是平移后的几何；把平移后的绝对坐标写进 `pipe_via`，下一轮重建时被当成平移前的用，
     偏移量正好是两次平移之差——现象是"绕行点明明算对了，重建后管线跑去了别处，仍然穿塔"。
     规矩：凡是要写进提示（下轮复用）的**绝对坐标**先减 `unfit_shift(cd)`；
     增量型提示（位移量、`t`）不受影响。
  ⑤ **严重级别要跟着"承诺"走**，否则要么误伤要么形同虚设：手工摆位的图记 `warning`
     （引擎无权替人改坐标），`layout.mode=auto` 记 `error`（**既然排版是引擎做的，
     就没有理由留下碰撞**）。这同时给出了"保证问题不再出现"的可验收口径。
  ⑥ **别用猜的尺寸排版**。`measure_equipment()` 在一张草稿图上真画一遍取包围盒与锚点偏移——
     塔 24×162、泵 11×11 差一个数量级；按"30×20 的格子"排出来不是压成一团就是散得读不出关系。
     锚点偏移同时让"预估管线"与实际出图口径一致（塔顶接管在正上方，不是几何中心）。
  ⑦ **图幅要跟着内容走**：5 台设备硬塞进 A1 的利用率只有 13%，`fit_to_sheet` 只平移不缩放，
     改不了这一点（HG 20519.2 自己就写着"P&ID 用 A1 横幅，**简单者 A2**"）。
     判据要**逐幅面试排**再比利用率——内容尺寸本身与图幅耦合，拿一个倒推另一个会自相矛盾。
  ⑧ **代理指标不能被"上一版记忆"污染**：代价函数里的预估管线**刻意不带** `pipes[].via`
     （绝对坐标 = 上一版走线记忆），否则一个过时的 via 能把「预估穿设备」锁死在同一数值，
     让几十种排版看起来完全一样、搜索原地不动。

### [2026-09-23] 用 ELK layered 重建版面分配（替换启发式"行数 × 对齐 × 间距档"）

> ⚠️ 本条**取代**下一条（[2026-09-22] 启发式版面分配）中的 ③：那个"行数 × 行内对齐 ×
> 间距档 + 坐标下降"的几何搜索已被 ELK layered 取代。下条记录的**工段划分、数量统计、
> 三类缺陷探测器与接管段走线**仍然有效——它们在这次重建里被完整保留。

- 需求类型：出图（版面质量的**来源**从"手写搜索"换成"成熟图布局算法"）
- 采用方案：
  ① 新建 `scripts/chemcad_elk.py`（**零依赖**纯 Python）：Eclipse Layout Kernel
     `org.eclipse.elk.alg.layered` 的八阶段——破环（Eades–Lin–Smyth 贪心）→
     分层（最长路 / 紧致收窄）→ 折行（ARD 切带）→ 虚拟节点 → 交叉最小化
     （层扫描 + 双侧相邻交换 + Barth–Jünger–Mutzel 逆序对计数）→ 层内排布
     （Brandes–Köpf 四向对齐取平均 + 拉直）→ 端口放置（FIXED_SIDE）→ 正交布线。
     选项字段名与 ELK 官方选项一一对齐，八个阶段全部**可单独调用**（为了能逐个单测）。
  ② `chemcad_layout.py` 退化为**域适配层**：设备→节点、命名锚点→端口（用真偏移）、
     管线→边（回流线照原样反着指，由破环阶段处理）；搜索空间从"几何自由度"
     换成 **4 档案 × 7 间距档 × 2 段排布 = 56 次真排**；代价函数从 7 项"预估"换成
     8 项（新增**转折点数**，`穿设备`/`管线交叉` 改为按落位坐标**实算**）。
  ③ 图幅判据从"装得下 **且** 利用率 ≥ 38%"改成**"最小装得下"**（理由见经验 ⑤）。
  ④ ELK 折点回灌出图：`plan["pipe_via"]`，优先级
     `规格写明 route/via` < `ELK 折点` < `迭代修正提示`。
  ⑤ `selftest.py` 新增 `[16]` 组（16 条）钉 ELK 八阶段；`[15]` 组改为钉
     "ELK 中间结果落盘 + 版面结构可断言"；文档对账数值同步到 **19 组 / 222 条**。
- 结果：成功。自动排版示例仍是 **符号重叠 0 / 文字压线 0 / 管线穿设备 0**，
  且各工段**交叉数 0**、ELK 走线**一条都不碰设备包围盒**；自检 18 组全过。
- 经验：
  ① **"走线不穿设备"可以从"后处理躲开"升级成"版面结构排除"**——这是换成 ELK 之后
     最值钱的收益，值得写清论证链：层内每个节点的纵向区间互不重叠 ⇒ 水平段沿某节点的
     y 走绝不会碰到同层另一台设备；竖段一律落在**层间隙**里（那里按定义没有节点）；
     长边走虚拟节点链，中间那几段走在**空着的那一格**上。三条合起来 ⇒ 穿设备不可能。
     结论：**换算法之前先想清楚"新算法的哪条不变量能替掉哪段补丁"**，
     否则只是换了个引擎、补丁一个没少。
  ② **Brandes–Köpf 的"块"必须整块合并，不能逐个连边**。第一版是"v 与中位邻居 m 对齐"
     逐步连，于是 `align` 链长度最多 2，块永远跨不过两层，直线段全丢；
     正确做法是处理第 i 层时把 v 与 **m 所在的整块**合并（`block_of` + `blocks[layer]`），
     块于是自动接到一条已经向下延伸若干层的竖直链上。
  ③ **相邻交换的交叉判定方向容易写反**：k1 在 k2 之前时，两节点的邻居对相交当且仅当
     `p > q`，即 `(p − q) × (k2 − k1) > 0`。写成 `< 0` 会把交叉数越"优化"越多，
     而且**不报错**——只有"构造交叉图必须降到 0"这条断言能抓出来。
  ④ **折行必须同时修两处"记录与几何不一致"**（一次全踩到）：
     (a) 段内布局只摆平了子图的端口（那些端口属于 sub、不是 g），段节点搬到全局坐标后
     `g` 上的端口还停在初始位置 → 跨段边画成一对 `(0,0)` 的零长线；
     (b) `g.layers` 还是**全局分层**，而段内丢掉跨段边后重算的分层可能不同
     → "同一层的设备 x 相同"这条会差 1 mm。**几何是对的、记录是错的**，
     所以修法是"按最终位置重放端口 + 按段内实际层重建 layers"，不是改几何。
  ⑤ **"利用率下限"不能当图幅判据——当间距是引擎的输入参数时它就是错的**。
     旧版用"无溢出 且 利用率 ≥ 38%"选幅面；ELK 版的分配步会主动把余量摊进间距把版面填到
     90%，于是"能不能填满"取决于**间距上限**而不是图纸大小：12 台设备的流程图会被判去用 A1。
     改成"最小装得下"之后，利用率只用来提示"这张确实偏空"。
     **教训：判据要跟着"什么是可调的"走；换了引擎，旧判据可能从"合理"变成"反向"。**
  ⑥ **多分量不能只用层间距去堆**。`_arrange_components` 第一版拿
     `spacing.nodeNodeBetweenLayers` 当堆叠净距，于是同一层里来自两个分量的设备
     中心距只有 34、比要求的同层净距 70 还近——**"层内不重叠"被无声破坏**。
     改成 `max(层间距, 2 × 同层净距)` 并再跑一遍 `_enforce_separation` 收口。
  ⑦ **断言要拿"包围盒中心"比，不能拿"落位基点"比**：基点 = 中心 − 各符号自己的包围盒
     中心偏移，而塔器（接管偏在一侧）与泵的偏移不同，基点必然不一样。
     第一版拿基点比，把"符号各自不对称"误判成"层带没建对"——
     **失败断言先怀疑断言本身**，别急着改代码。
  ⑧ **把实现边界写进模块头，比写进文档更可靠**。本次在 `chemcad_elk` 头部明写三条边界：
     `NETWORK_SIMPLEX` 只做了「收窄」阶段（不保证全局最优）、不做超边合并布线、
     只支持 `direction=RIGHT`（其余方向直接抛错）。**宁可让调用方拿到 ValueError，
     也不要静默按横向画出一张方向不对的图**——`ValueError` 是能被测的，
     "画歪了"不能。
  ⑨ **换了引擎之后，代价函数量的东西可能已经变了性质**。旧版用 `ortho_path` 的默认走线
     量"穿设备"；接入 ELK 折点当默认走线之后，ELK 走线**结构上不穿设备**，
     于是这一项变成"给一个即将被修掉的问题打分"——它以 29.9 压过其余各项，把整场搜索带偏。
     改成"**能取到 ELK 折点就用折点**"（规格显式写了 `route`/`via` 的除外，引擎不覆盖它），
     该项降到 20.5，剩下的正是跨工段管线与显式走线的**真实残差**。
     **教训：代价函数要与"最终会画出来的东西"同口径；口径漂了，搜索就在优化一个假目标。**
     附带一条：同一套过滤规则（哪些管线用 ELK 折点）在**代价**与**出图**两处必须一致，
     否则两处量的是两张不同的图——所以抽成 `_cost_paths` 与 `_elk_via` 时把
      "规格显式给了 route/via 就不覆盖"这条写在两处的 docstring 里互相指认。

### [2026-09-23] 用 A*（Hanán 网格）重做管线避障：三类缺陷从"事后躲开"变成"搜索不产出"

- 触发：要求**不许出现**文字压线 / 符号重叠 / 管线穿设备。ELK layered 能保证
  **版面结构**上不穿设备，但 ① 跨工段管线不在 ELK 图里、② 阀门仪表文字参与后会造成二次遮挡
  ——版面再干净，落到出图阶段仍需要一层真正的避障。
- 做法：新增零依赖模块 `scripts/chemcad_route.py`（Hanán 网格 + 四向 A*，
  状态含"进入方向"以便给折弯计价），硬障碍来自**与校验器同口径**的矩形：
  设备本体 + 文字框；阀门仪表做软障碍。走线优先级改为
  `规格显式 route/via` < `ELK 折点` < `A* 路径` < `迭代修正提示`。
- 结果：成功。自动排版示例端到端 **符号重叠 0 / 文字压线 0 / 管线穿设备 0**，
  preflight 0 错误 0 警告，15 条管线**全部 relax=0**（无需降级）；耗时 6.8s → 3.1s。
- 经验：
  ① **搜索半径必须是"够用就好"，不能取最大值**。固定 `region_pad=260` 对一段 124 mm
     的短跳是荒谬的：搜索区域被撑成 520×520，把全幅面 100+ 障碍全卷进来，网格涨到
     194×241 → 展开超预算 → 两条管线无解 → 退化成直线穿设备 66 mm。
     改成 `clamp(端点距离 × 0.55, 60, 260)`、失败才放宽到全幅后，15/15 全解。
     **搜索量对半径是平方级的，别把每条管线都当成全局最短路来解。**
  ② **展开预算要随网格缩放，不能是常数**。固定 24000 时，122×163 的网格也压不出来
     （实际需求 28148）。改成 `clamp(4 × 节点数, ≥24000, ≤150000)` 后同样速率下全解。
     **节点数才是量纲正确的预算标尺。**
  ③ **接管段的定义是"走到本体之外"，所以必须行军，不能试三个比例**。旧实现试
     `stub × (1.0, 0.7, 0.4)`，三者全在本体内就退回原点——而反应器锚点常常
     **嵌在本体 7.6 mm 深处**。于是 A* 起点站在硬障碍里，四邻全不可达 → 搜遍全网超时
     → 只能 `relax=2` 把设备降级成软障碍穿过去。**"管线穿设备"就是这么来的。**
     改成逐步外移到脱离所有硬设备为止（上限 40 mm），该线从穿 42 mm 降到 1.15 mm。
  ④ **⚠️ 布线跑在 `fit_to_sheet` 之前，此刻坐标是"版面自身坐标系"，不能拿图纸幅面当边界**。
     模块头的注释早就警告过"默认 None，别乱开"，可 `route_pipes` 仍然自作主张用
     `(0,0,W,H)` 生成边界墙 `x<4`。某反应器本体落在 `x∈[0, 49.3]`（内容原点就在 0），
     贴左整片区域被判非法，向西出线的管线**永远走不出那道墙**。
     改成由**内容自身包络 + 余量**求边界（同坐标系），两条"无解"当场消失。
     **教训：坐标系不一致的 bug 会伪装成"算法搜不出来"，先问"我在跟谁比"。**
  ⑤ **差 0.01 mm 不算画错，但足以把测试变红**。后端块插图元是
     `local + insert基点` 重建的，与 IR 里已算好的世界坐标是同一量的两种浮点算法，
     差 1 ULP；真值落在 `.xx5` 舍入边界上时 `round(x,2)` 会把两者送到边界两侧。
     A* 改变了全部坐标，概率被放大 —— 24 条线段集体错位 0.01 mm，"几何等价"凭空变红。
     修法是按**一一对应的容差匹配**来判（仍要求条数/图层/一配一），而不是按二进制全等。
     **0.01 mm 是线宽 0.15 mm 的十五分之一，它是浮点噪声，不是几何错误。**
  ⑥ **负对照的判据必须跟着机制走**，否则会退化成"证明我没删错代码"的假绿。
     旧断言「接管段降级 → 重新出现穿设备」在 A* 上线后就失效了（穿设备被搜索结构性排除）。
     实测四种情形后拆成两条各钉一头：
     `关掉 A* → pipe_through 0→4`（不穿设备归 A*）；
     `接管段降级 → 穿设备仍 0 但压线/重叠合计 0→20`（尽早脱离本体归接管段）。
     **写负对照前先量一遍：机制换了，"缺了它会坏在哪"也就换了。**

### [2026-09-23] 工段框图工作流：选址与落笔拆两步，靠 `fit.shift` 对齐坐标系

- 需求类型：出图（用户指定"先框图 → 设备入框 → 再填流股信息框"的工作流）

     各写一个 14.0 迟早漂移——收敛成一个模块级常量。
  ③ **整批要么全画、要么全不画**，别边找边画：边画会让"放得下的前几个"落纸、
     "放不下的后几个"消失，读图的人会误以为那几个工段**没有流股**。
     放不下就退回整张物料平衡表（评审单列的 1.5 分必备件），宁可不分表也不缺项。
  ④ **逐件取舍 > 整框跳过**：一个角压到说明框就只丢那个角，不是丢整个工段标记。
     工段框的价值是"一眼看出哪几台设备同属一段"，少一段就少一段信息。
  ⑤ **工段划分要独立于排版模式**。用户工作流是"工段设备分配完 → 画框图"，
     "分不分段"跟"要不要 auto 排版"是两件事；`layout.mode=off`（用 bkp 自带坐标）
     也得能画框。所以 `build()` 单独算一份 `_sections`（复用 `L.split_sections`），
     不依赖 `plan_layout` 的产物——否则 off 模式下 `section_frames` 永远是 0。
  ⑥ **段名要避设备本体，不止避家具**。段名写在框上沿内侧，那里可能正是设备轮廓线；
     只避家具仍会报"SECT 线压 EQUIP"。段名的 `avoid` 清单 = 家具 + 本工段设备包围盒，
     角标只避家具。压到设备就整段名不画（保留角标），比压线扣分好。

### [2026-09-23] 重新学习接续标志（offpage）真实画法：框答"去哪张图"，旁注"去/自哪台设备"

- 需求类型：回源核对作图规范（用户要求"重新学习接续标志的使用方法和作图规范"）
- 回源对象：两份真实参赛 PFD——① 浙江工业大学 `Drawing1.dwg`（本技能 `CONNECTOR_*` 常量来源，
  一张图例，三种画法 + `10-文本` 层三行 MTEXT 图例说明）；② 南京工业大学
  `PFD-2018.dwg`（`5-接续符号` 层 91 LWPOLYLINE+15 CIRCLE、`5-来去归属文字` 层 88 处 TEXT）。
- 几何核对（结论：**本技能几何基本正确，无需改尺寸**）：
  * 箭头：长 3.0 / 高 6.0 —— 与 `CONNECTOR_ARROW_LEN=3.0`、`CONNECTOR_BOX_H=6.0` 一致；
  * 长框（跨工段）≈40、短框（同工段）=10 —— 与 `CONNECTOR_BOX_MIN=10.0`、长框=文字宽+3 一致；
  * 界区圆 r=5.0 —— 与 `CONNECTOR_PLANT_R=5.0` 一致。
  * 即：框+箭头+（跨厂）剖面线圆这套**带框**画法对，真图就是带框的（不是自造空心三角）。
- **唯一的真实差异在"框旁文字写什么"**：
  * 本技能原先只写「流股号 + T/P/W/相态」（用户硬约束的物流标注）；
  * 真实图（南工大）在框旁另写**「来去归属文字」**：`物料/来源 + 去/自 + 目标(设备位号/界区)`，
    例：「脱轻烃塔塔顶产物去T0301」「原料苯自总厂来」「焦油去总厂」。
    框里只答"去了哪张图/工段"，这条文字答"跨过去去/来自哪台设备"——读图人最关心的是后者。

  * `bkp_to_pfd._offpage` 新增 `dest` 字段：按 `here`/`there` 设备 + 流股流向

### [2026-09-23] 换幅面的"试探"与"定稿"要分开给预算（性能）

- 需求类型：性能（`sheet="auto"` 时出图慢）
- 现象：一份 8 台设备的拆图，建图要 **53.5s**——设备这么少不该这么慢。
- 根因：`build_with_layout` 的换幅面循环里，**每次都跑 `max_rounds` 轮完整迭代修正**。
  `sheet="auto"` 最多 5 个幅面 × 4 轮 = 20 次完整建图。
  但"这个幅面装不装得下"由 `_needs_bigger_sheet`（只看 overflow / 压家具 /
  流股表放不下）**一次建图就能判断**——迭代修正改的是设备微移与走线，**对选幅面
  毫无帮助**。
- 改法：试探轮用 `probe_rounds=0`（只建一次），只有**确定不再换幅面**的那次
  才用完整 `max_rounds` 定稿。
- 结果：8 台那张 **53.5s → 32.9s**；9 台那张 1.0s。12 张拆图批量出图可跑完。
- 经验：**先问"这个循环要回答的问题是什么"，再决定给它多少预算**。
  换幅面循环回答的是"装不装得下"，不是"版面修得漂不漂亮"——
  用"修版面"的成本去回答"选幅面"的问题，是纯粹浪费。

## 五、术语速查（教学式解答用）

| 术语 | 大白话解释 |
|------|-----------|
| P&ID | 管道及仪表流程图——画"设备怎么连、量在哪测、由谁控制"的图 |
| PFD | 工艺流程图——只讲物料走向与工艺条件，不画控制回路细节 |
| 设备位号 | 设备的名字牌，如 `T-101`＝第一主项的 1 号塔 |
| 仪表位号 | 仪表的编号，如 `FIC101`＝流量(F)+指示(I)+控制(C)+回路01 |
| 锚点 Anchor | 符号上预留的"插口"，管线只能接在插口上，不许接符号中心 |
| 正交布线 | 线只走水平/竖直，转弯只能 90°，**禁止斜线** |
| 气开 / 气闭 | 失气时阀自动开 / 自动关——安全关键属性，国标要求必注 |
| 串级控制 | 主控制器不算最终值，它去"改副控制器的设定值"，两级套着控 |
| 前馈控制 | 提前测扰动、提前动作，不等被控量变了才反应 |
| 分程控制 | 一只控制器输出分成两段，分别开两只不同的阀 |
| 多冲量 | 用多个测量量一起决定一个输出（如锅炉液位+蒸汽量+给水量） |
| 图层 Layer | 把图按类型分成一叠"透明纸"，可单独开关、改色、锁线宽 |
| 线宽 粗/中粗/细 | 0.6~0.9 / 0.3~0.5 / 0.15~0.25 mm（HG 20519.1 硬要求） |
| 图块 Block | 一组图形打包成可反复引用的整体（阀门、泵、仪表圆…） |
| 出图后端 | **默认 DWG（经 AutoCAD COM）**；另有 DXF / 直画 AutoCAD(COM) / SCR / LISP，同一份图 |
| `preflight` | 出图前的自检——图层/线宽/正交/位号/闭环一次过一遍 |
