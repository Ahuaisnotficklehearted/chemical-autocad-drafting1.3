# 定位与提取（Locate & Extract）

出图是**正向**（方案 → 图），本文档讲的是**逆向**（图 / 模型文件 → 结构化信息）。
两者共用同一套坐标与图层约定，所以提取出来的东西能直接喂回出图流程。

工具：`scripts/chemcad_locate.py`（**零依赖**，只用标准库）。

---

## 一、第一原则：先切作用域，再取对象

**一个文件里，同名对象会出现在多个作用域里。**

| 文件类型 | 作用域 | 撞车实例 |
|---|---|---|
| Aspen `.bkp` | 顶层 `PFSVData` + 每个层级块自己的 `PFSVData` 页 | 层级块内部的模块/流股**再存一份、名字还不带前缀** → 同一个流股名出现两条、位置还对不上 |
| DXF | `ENTITIES`（模型空间）/ `BLOCKS` 里每个 `BLOCK` / `TABLES` | 图面上有 `T-101`，块定义内部也有个 `T-101` |

混读的后果是**静默**的：不报错、数量看着也"不少"，只是对象出现两次、位置对不上。
所以本模块的第一件事永远是**按作用域切开**，再在指定作用域里取对象。

```bash
python scripts/chemcad_locate.py scopes 图.dxf          # 列出作用域 + 同名撞车自查
python scripts/chemcad_locate.py scopes 图.dxf --json o.json
```

DXF 侧另有两条纪律：

* **匿名块**（`*Model_Space` / `*Paper_Space` / `*U123` 动态块）的几何要参与"全图范围"统计，
  但**不参与按名定位**——用户说的 `T-101` 不可能是 `*U123`。
* 段名必须取 `SECTION` 的**下一对** `2/<段名>`。取错位置会把下一个实体类型当成段名，
  于是 `BLOCKS`/`ENTITIES` 全认不出、作用域数静默变 0（**本模块自己踩过并已钉回归**）。

## 二、能力清单

| 能力 | 函数 | 要点（为什么这么做） |
|---|---|---|
| 编码鲁棒读取 | `read_text_robust` | 逐级降级 `utf-8-sig → utf-8 → gbk → latin-1`。**不用 `errors="replace"`**：它把"编码错配"变成看不见的 `U+FFFD`，正则照跑、中文全成问号——静默失真比报错难查。`latin-1` 只作兜底（逐字节映射、永不失败），并由 `is_lossy()` 标记"中文不可信" |
| 作用域切分 | `split_dxf_scopes` / `parse_bkp_scopes` / `pick_main_bkp_scope` | 见上节。`.bkp` 主段取**对象数最多**的顶层段 |
| 同 id 去重 | `dedupe_keep_best` | 保序留"更完整"的那份（有折线/几何者胜）。**不是**"后者覆盖前者"——文件顺序是工具写的顺序，不是可信度顺序 |
| 折线重建 | `merge_paths` | 一条管常被拆成多段（换图层/绕设备/跨图框）。不合并，则"拐了几个弯""多长"全不准 |
| 折线定向 | `orient_path` | 折线**不保证方向**。按已知源/目的位置校正；两端都未知时**原样返回，不猜** |
| 端口反推符号尺寸 | `infer_symbol_sizes` | ① 逐符号取**中位数**（不是均值）——有人把线画到圆心、画到很远，极端值必须在符号内就剔掉；② 全场再取一次中位数作统一基准；③ 收敛到基准的 0.65~1.4 倍（同图不该一大一小），基准夹到 `[0.4, 2.5]` |
| 轮廓裁切 | `clip_to_outline` / `clip_circle` / `clip_rect` / `clip_poly` | 按符号**真实轮廓**（圆/矩形/三角形）把线端裁到边界，否则线画进符号里＝"管线穿设备"，而正交性/线宽/位号校验**一条都查不出**。多边形用**射线法 + 二分 40 次**逼近 |
| 点拾取 | `pick_at` | 先包围盒粗筛，多候选取**中心最近**——符号是离散的，重叠区里离中心近的几乎总是用户要点的那个 |
| 文字列扫描排序 | `order_column_scan` | 图纸是**分栏**的（说明框/明细表/图例栏各一列）。纯按 y 排会串栏，纯按 x 排会打乱栏内顺序。列边界按 `3×平均字高` 自适应断开 |
| 测距 | `closest_distance` | 同时给**中心距**（"摆得匀不匀"）与**包围盒净距**（"够不够净空"，相交时为 0 ＝ 相撞） |
| 文字两层清洗 | `unescape_dxf` / `strip_mtext_codes` / `text_bbox` | ① DXF 转义 `\U+XXXX`；② MTEXT 格式码 `\f..;`/`\C..;`/`\P`/`{}`/`%%c`。不剥就看不清真文字。文字必须有**有面积的 bbox**（按 `中文=1 字高 / ASCII=0.55 字高` 估宽），否则拾取、排序、测距在文字上全部退化成"一个点"，且不报错 |
| `.bkp` 全量提取 | `parse_bkp_case` | 见下节 |

> 📌 **字宽约定只定义一次**：`text_bbox` 用的是 `chemcad_symbols._text_w` 的同一条规则
> （中文 1 字高 / ASCII 0.55 字高）。出图与提取必须一致，否则"提取量到的宽"和"画出来的宽"对不上。

## 三、Aspen `.bkp`：不装 Aspen 也能看流程

`.bkp` 是**文本**文件，流程图数据分三处：

| 内容 | 位置 | 提取函数 |
|---|---|---|
| 模块类型 + 坐标 + 图标名 | PFS 段 `BLOCK` / `ICON:` / `At x y` | `parse_bkp_objects` |
| 流股拓扑（谁产谁用） | `FLOWSHEET` 段 `BLOCK BLKID=… BLKTYPE=… IN=(…) OUT=(…)` | `parse_bkp_flowsheet` + `build_stream_connections` |
| 流股路由折线 | PFS 段 `ROUTE n n` + `r/t/x/y … 0` 序列 | `parse_bkp_objects`（+ `merge_paths` / `orient_path`） |
| **工艺结果**（T / P / 质量流量 / 体积流量 / 摩尔流量 / 气相分率） | `DSET STREAM MATERIAL <名> RES_STR @L_n (…)` | `parse_bkp_stream_results` |
| 单位集（据此给裸数字配单位） | `SETUP "UNITS-SET" … DESCRIPTION DESCRIPTION = "…"` | `parse_bkp_units` |

```bash
python scripts/chemcad_locate.py bkp 案例.bkp --json case.json
```

三条容易踩的：

1. **一个 bkp 可能存多页 PFD**（顶层一页 + 层级块自己一页），只读顶层那页。
   判据：**对象数最多**的段。
2. **子流股标记必须剔除**（`M1-2`、`MIXED`、`CISOLID`、`NC`、`WORK`、`HEAT`…）。
   不剔的话 `IN=(FEED MIXED-NC)` 会把 `MIXED` 当成一条真流股——凭空多出一条"物料线"，**且不报错**。
3. **单位集必须顶上去**：`RES_STR` 只给裸数字，"温度 = 45" 是 45 ℃ 还是 45 K，
   决定整张工艺数据表的含义。`METCBAR` 这类代号要从描述文本里推断。

> ✅ **经验订正**：本技能经验库旧条目曾写"流股结果（T/P/F）不在 bkp 里，必须留给模拟报告"——
> 那是不完整的。`DSET STREAM … RES_STR` 段**确实带** T/P/质量流量/体积流量/摩尔流量/气相分率。
> 而**管径与设备规格**不在 bkp 里属于**预期之内**——PFD/P&ID 本来就不需要这两项
> （详见 §七 第 5 条），**不算缺失**。

输出结构（`parse_bkp_case`）：`blocks`（含 `category` / `outline` / 反推 `half`）、
`streams`（含 `source` / `dest` / `polys` / `length`）、`stream_results`、`units`，
以及 **`unresolved`**——解析不出来的项**列出来**，不留空、不编造。

## 四、与既有脚本的分工（别重叠）

| 脚本 | 定位 | 一句话 |
|---|---|---|
| `inspect_dxf.py` | **轻量罗列** | "这张图里有什么"：图层 / 块 / 实体计数 / 文字样例 |
| `chemcad_locate.py` | **定位与提取** | 实体级解析（坐标、bbox、连通性）+ 几何推理（尺寸反推、折线重建、裁切、拾取、测距） |
| `read_dwg.py` | 读**运行中的 AutoCAD** | 走 COM；本模块读**落盘文件**（DXF / bkp） |
| `check_dxf.py` | **合规校核** | 正交性、线宽、图层 |
| `preview_dxf.py` | **目视** | 出 PNG 给人看 |

典型组合：

```bash
# 评审一张别人给的图：先看结构 → 再定位关键对象 → 再量间距 → 最后目视
python scripts/chemcad_locate.py scopes 图.dxf
python scripts/chemcad_locate.py locate 图.dxf --tag T-101
python scripts/chemcad_locate.py distance 图.dxf --a T-101 --b E-102
python scripts/preview_dxf.py 图.dxf --out 图.png
```

## 五、交付前质量闭环（四条，缺一不可）

提取出的东西**不能只看"跑通了"**。逐条核对：

1. **来源可回溯**：每条结果都带 `source` 与 `scope`。`.bkp` 解析结果带上 `main_scope`（主段取法）
   与 `scope_count`（段数）——**先证明读的是哪一页**，再谈内容。
2. **不编造**：`unresolved` 必须被逐条处理或如实交代。空着不说 = 把"没取到"伪装成"没有"。
3. **单位落实**：数值必须带单位（`units` 里的 `recognized: no` 要显式告知用户"单位未识别，数值含义待核"）。
4. **目视复核**：几何类结果（折线、裁切、尺寸）**必须出图看一眼**——自动校核查不出"丑"，
   线画进符号里、折线接错头，都只有看图才发现。

## 六、CLI 退出码契约（供 CI / 批处理）

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 文件不存在 / 打不开 |
| 3 | 其他异常（**不抛栈**，一行错误到 stderr） |
| 4 | 按条件查不到对象（`locate` / `pick` 未命中）——是"查无此物"，不是"程序出错" |

把"未命中"与"程序错"分开，是为了让批处理能区分"图上真没有这个位号"和"解析失败"。

## 七、已知边界

1. **不解析 XREF**（外部参照）：文字/图元在外部参照里时提取不到，会表现为"结果为空"。
2. **`POLYLINE` 只收顶点**：凸度（`42`）不还原为圆弧——折线按折点处理，圆弧段会被"拉直"。
3. **文字宽度是估算**（中文 1 字高 / ASCII 0.55 字高），与绘制端一致，但**不等于真实字宽**；
   用于拾取/排序/溢出预判足够，不可用于精确排版核算。
4. **`.bkp` 只读主 PFD 段**：层级页内的细节流程图不提取（要看得先明确"看哪一页"）。
5. **管径 / 设备规格：本技能不要求，也不去识别。**
   `.bkp` 里没有这两项是**符合预期**的——PFD 的图面内容本身就**不含管径与设备规格**：
   管径属于**管道布置图 / 管道特性表（管线表）**，设备规格属于**设备数据表 / 设备一览表**。
   所以：
   * **不要把「取不到管径 / 设备规格」当成缺失**，更**不要写进 `unresolved`** 去追问用户——
     `unresolved` 只放"本该取到却没取到"的东西，这两项属于"本任务不需要"。
   * 用户**已给出**就直接用（照标）；**没给就不补**，不编造。
   * 仅当用户明确要**管道布置图 / 管线表 / 设备表**时，才需要另行取数——仍**不得编造**。
   * （机械图不在本技能范围内，不存在"机械图仍需设备规格"这个例外。）
