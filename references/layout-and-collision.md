> 域适配层：`scripts/chemcad_layout.py`（化工语义 → ELK 图 → 设备基点）
> 通用引擎：`scripts/chemcad_elk.py`（**零依赖**的 Eclipse Layout Kernel `layered` 算法实现）
> 探针：`chemcad_engine.detect_symbol_overlaps` / `detect_text_over_lines` / `detect_pipe_through_equipment`
> 回归：`scripts/selftest.py [15]`（适配层）/ `[16]`（ELK 引擎）/ `[17]`（A\* 布线器）

## 2026-10-06工艺回路与工段页规则

`chemcad_process_layout.recognize`只接受明确`column.*`型式、塔顶冷凝/冷却换热器与回流名称、实际有向返回闭环；再沸回路要求明确再沸名称、换热器型式及塔↔换热器双向连接。资料不足继续普通ELK，不按设备类别猜用途。回路成员尽量同工段，跨工段清单仍以项目明确归属为准。

已识别回路在主流程上方/下方排成员，并给真实接管、完整标注、并行线及固定底部文字列留空间。相关单链主流程从左向右，多分支仍保留拓扑排版；设备与物流不以“样本外观像”替代项目连接。整图超容量进入现有图幅选择/拆张规则，固定A1工段页超容量报错。

`chemcad_sections.py`处理页面级行列，不重排前工段；每工段右端仅一张汇总表。纯平移、实际框边150mm净距，详见[pfd-sections.md](pfd-sections.md)。浮点噪声比较容差0.001mm用于判同轴，不开放旁侧3mm禁区；最终落笔几何仍校核。

## 1. 为什么拆成两个模块

`chemcad_engine.py` 管的是**几何是否合法**，`chemcad_layout.py` 管的是**版面是否好看**。
两者判据根本不同：

| | 逐实体型（引擎） | 关系型（版面模块） |
|---|---|---|
| 例子 | 正交布线、线宽分档、位号构成、文字高度、调节阀必注 | 符号重叠、文字压线、管线穿设备、设备太挤、图面空半边 |
| 判据 | 看**一个**实体就能判 | 必须看**两个以上**对象的关系 |
| 过去怎么办 | 校验器兜底 | **只能出图目视**（技能文档过去正是这么承认的） |

关系型判定的共同前提是**每个对象都要有真正的面积**。最容易踩的坑：

> `Text.points()` 只返回**基点**。直接拿它算包围盒，文字会退化成"一个点"，
> 「文字压线」永远为假——校验器写了也没用。所以引擎补了 `text_rect()`（含旋转）。

而**几何怎么算出来**这件事，又一次拆开了：`chemcad_elk.py` 只认识有向图与节点尺寸，
**完全不认识化工**——设备、管线、工段都是 `chemcad_layout.py` 的事。
拆开的好处是 ELK 的八个阶段可以**逐个单测**（破环对不对、分层可不可行、
交叉数降没降、层内有没有重叠），不必每次都把图建出来、再靠目视判断（回归 `[16]`）。

## 2. 五段式

```
spec ──► ① split_sections   工段划分（显式 / 设备字段 / 流股连通性 + 层序平衡对切）
     ──► ② count_equipment   每段设备数量与构成
     ──► ③ plan_layout       ELK layered 分配（建图 → 破环 → 分层 → 折行 → 交叉最小化
                             → 层内排布 → 端口 → 正交布线；档案 × 间距档 × 段排布 搜索）
     ──► ④ detect → repair → 重建    迭代修掉三类版面缺陷
     ──► ⑤ apply_plan        按计划平移设备（实体 / 基点 / 锚点一起挪）
```

## 3. ① 工段划分与命名（三级优先）

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 规格顶层 `sections:[{id,name,equipment:[…]}]` | 显式指定，不做任何推理 |
| 2 | 每台设备的 `section` 字段 | 按字段值分组，组序按流程 |
| 3 | **启发式自动划分** | 无上面两项信息时启用 |

启发式自动划分三步：

1. **建设备邻接图**：把 `pipes` 里两端**都是设备**的管线连成边
   （一端接到跨图接续/字面坐标的线不参与——否则"产品去罐区"会把所有工段粘成一坨）。
2. **切硬分界**：`pipes[].section_break = true` 的边先切断。
3. **弱连通分量 + 层序平衡对切**：分量内设备数超过 `max_per_section`（默认 8）时，
   先按**流程层序**（Kahn 拓扑序）排好，再在最均衡处切一刀，递归处理两半。

   为什么是"层序 + 平衡"而不是通用最小割：流程图的工程语义就是**沿工艺方向分段**
   （反应段 → 分离段 → 精制段）。按层序排好后切，切出来的段既在流程上连续、
   数量上也均衡——这正是工程师手工分段的做法。有环（回流/循环物流）时环内节点按
   规格出现顺序兜底，保证**结果可复现**。

**段的切分点优先落在「职能边界」**（`_split_component(func_of=…)`）：
纯按数量对半切，会把"塔 + 塔顶冷凝器 + 回流罐"从中间劈开——回流罐跟塔本来是一伙的。
做法是先按各台设备的**工艺职能**筛出候选切点，再在候选里挑最均衡的；
一个职能边界都没有时才退回纯数量对半分。（实测：示例的 12 台设备从"2 段各 6 台"
变成"4 / 3 / 5 三段"，塔系不再被劈开。）

### 3.1 段名 = 段内**最上游设备的工艺职能**

**按"数量最多的类型"取名会撞车，也读不出流程**（一个装置里两个"换热工段"毫无信息量）。
段的"名分"由**段首那台设备**决定——一个工段之所以成为工段，是因为它从某个职能开始。

`equipment_function(eq)` 的取值优先级：**设备名称 > 类型 > 位号**。

| 依据 | 为什么排这个序 |
|---|---|
| **名称** | 信息最多：「原料进料泵」与「回流泵」的 type 都是 `pump`，但前者是**进料**职能、后者属**储存与缓冲**段的输送 |
| 类型 | `tower` / `pump` / `exchanger`… 只有类别，不知职能 |
| 位号 | `P-` / `T-` / `E-`… 仅在前两者都判不出时兜底 |

职能表（`_FUNCTION_RULES`，**表序即匹配优先级**）：
`进料与预处理` · `反应` · `分离` · `换热` · `输送与加压` · `精制` · `储存与缓冲` · `公用与火炬`

段名 = `f"{段首职能}工段"`；重名才编号。`sections[]` 里同时记 `function`（职能）
与 `upstream`（哪台定的名），报告里能看到"这段的段首是谁"，人工改名也有依据。

显式 `sections` / 设备 `section` 字段给的**名字优先**，`function` / `upstream` 照样算。

**段序 = 流程顺序**（不是规格里的先后），**工段从左到右依次排开** —— 与读图习惯一致。

## 4. ② 设备数量统计

```python
L.count_equipment(spec, sections)
# {"total": 12, "sheet_total": 12,
#  "sections": [{"id","name","count":4,"types":{"pump":1,"exchanger":2,…}}, …]}
```

数量不是只用来"报个数"——它是**间距额度的分摊基数**：段里设备越多，
层带（以及折行后的排数）越多，能摊到的间距道数也越多（见 §5.4）。

## 5. ③ ELK layered 版面分配

### 5.1 量尺：用真符号量，不猜格子

`measure_equipment()` 在一张**草稿图**上把每台设备真画一遍，取包围盒尺寸与
**命名锚点的相对偏移**。塔器是 24×120、泵是 11×11，差一个数量级；按猜的尺寸排版，
出来不是压成一团就是散得读不出关系。

锚点偏移同时用于两件事：ELK 的**端口坐标**（管线从法兰出去，不从设备壁的空白处出去）
与代价函数里的**走线预估**。

### 5.2 化工图 → ELK 图：三条翻译规则

`build_elk_graph()` 把**一个工段**翻成一张 ELK 图。三条规则都是"不得不这样"的：

| 规则 | 为什么 |
|---|---|
| **设备 = 节点**，尺寸用真实符号包围盒（含接管法兰） | 布局不猜尺寸；接管也要占地方，否则"离接管 1 mm"的设备会被排到撞上 |
| **端口 = 该设备被引用到的命名锚点**，位置用真锚点偏移、所在边由出线方向决定 | 接管法兰在哪儿，管线就只能在哪儿出；合成端口（按边均分）会把管子接到壁面空白处 |
| **管线 = 边**，方向 = 流程方向；**回流线照原样反着指** | 回流线由破环阶段统一处理（`break_cycles`），**不在建模时就掰正**——掰正会丢掉"这是一条回流"的信息，也会让破环阶段无从判断该反转哪条 |

只建**两端都是本工段设备**的管线。跨工段管线不在段内建图：段是独立排版的，
把跨段管线塞进某一侧会让那一侧的层序被别段设备牵着走；跨段管线由出图阶段的
布线（`ortho_path` / 接管段走线）+ 迭代修正处理。

### 5.3 八个阶段（对应 `org.eclipse.elk.alg.layered`）

| 阶段 | ELK 选项 | 化工图上的含义 |
|---|---|---|
| ① 破环 | `cycleBreaking.strategy = GREEDY` | **回流线**（塔顶回流、再沸器返塔、循环物流）反转，使图可分层 |
| ② 分层 | `layering.strategy` = NETWORK_SIMPLEX / LONGEST_PATH | **第几层 = 流程深度**。"每条管线至少跨一层"是唯一硬约束，层号是解出来的 |
| ③ 折行 | `wrapping.strategy = SINGLE_EDGE`，`cutting.strategy = ARD` | 一个工段太长就**分排**（流程图分排绘制），否则图面成一条极扁的长条 |
| ④ 虚拟节点 | 内部阶段 | 长边在每层插一个占位节点，它占的那道宽正是走线之间应有的净距 |
| ⑤ 交叉最小化 | `crossingMinimization.strategy = LAYER_SWEEP`，`thoroughness = 7`，`greedySwitch.type = TWO_SIDED` | 层扫描 + 双侧相邻交换，把管线交叉压到最小（示例各工段交叉数 = 0） |
| ⑥ 层内排布 | `nodePlacement.strategy = BRANDES_KOEPF`，`bk.fixedAlignment = BALANCED`，`bk.edgeStraightening = IMPROVE_STRAIGHTNESS` | 四向对齐取平均 → **直线段最多**且左右对称（不是"多试几次碰运气"） |
| ⑦ 端口放置 | `portConstraints = FIXED_SIDE` | 真锚点偏移原样采用 |
| ⑧ 边布线 | `edgeRouting = ORTHOGONAL` | 正交折线，竖段走层间隙、水平段走节点纵坐标 |

**BALANCED 为什么安全**：四次对齐都是**保序**的（层内先后次序不被破坏），
而"同层净距 ≥ 要求值"是一组线性不等式——线性不等式的可行点取平均仍可行。
所以"取平均"不可能凭空造出重叠。

### 5.4 搜索空间：档案 × 间距档 × 段排布

自由度只有三样，而且每一样都写在 ELK 的术语里（`ELK_PROFILES` / `SPACING_SCALE`）：

| 变量 | 取值 | 说明 |
|---|---|---|
| **ELK 档案** | 4 档 | 分层策略（网络单纯形收窄 / 最长路）× 层内对齐（四向平均 / 左上）× 层内排布（Brandes–Köpf / 简单中位） |
| **间距倍率** | 7 档 | `1.0 / 1.35 / 1.8 / 2.4 / 3.2 / 4.2 / 5.4`，乘在 ELK 的间距参数上 |
| **段排布** | `row` / `grid` | 工段并排 / 超宽换行 |

4 × 7 × 2 = **56 次真排**（`MAX_EVALS = 64`），由确定性代价函数挑最优。
无随机数，所以同一份规格两次结果完全一致（回归里钉了这条）。

**间距基准与上限**（间距是 ELK 的**输入参数**，放大它就是"把余量摊进间距"）：

```
spacing.nodeNode                = 14 × scale   ≤ 55
spacing.nodeNodeBetweenLayers   = 34 × scale   ≤ 72
spacing.edgeNode                = 8（固定）     spacing.edgeEdge = 6（固定）
section_gap                     = 26 × scale   ≤ 72
```

`spacing.nodeNodeBetweenLayers = 34` 不是随手取的：竖段走在层间隙里，
而 ELK 的接管段长为 `min(spacing.edgeNode, 9) = 9`，所以层间距必须
明显大于 `2 × 接管段`——否则塔顶接管刚出去就贴到下一层设备上。

**段内折行的目标带宽**取 `可用宽 × 0.90 ÷ 段数`：一段排得太宽会把别的段挤到下一排，
一段排得太窄又会折出很多排，两者都由代价函数兜住。

### 5.5 代价函数（8 项，越小越好）

```
溢出版面      ×400    内容超出可用区（最不可接受）
长宽比失衡    ×40     |ln(内容长宽比 / 可用区长宽比)|
留白失衡      ×30     ((利用率 − 81%) / 81%)²
净距不足      ×25     实际用到的间距 < 舒适值（= 0.22 × 平均符号尺寸）
穿设备        ×60     按落位坐标实算：每条管线让开管口后仍在设备体内的走行长度
管线交叉      ×18     实算折线两两真交叉数（轴对齐线段严格相交，共端不算）
转折点数      ×10     Σ(每路径折点数 − 2)，按条数归一
管线总长      ×6      Σ 路径长度 / (可用区宽 + 高)
```

前四项管"版面松紧"，后四项管"读图顺不顺"。**分项会写进报告**，
所以"为什么这么排"是可解释的，不是黑箱。

与旧版最大的区别：`穿设备` / `管线交叉` / `转折点数` 现在是**可算的几何事实**
（按落位坐标实算，与最终出图的几何同口径），不再是"预估"。

> ⚠️ **走线类分项按"实际会画的线"算，不按默认正交**。切换 ELK 之后这两者不再是一回事：
> 出图时会把 ELK 折点当默认走线（§5.6），而 ELK 的走线**结构上不穿设备**。
> 若代价仍按 `ortho_path` 的默认走线去量，就是**给一个即将被修掉的问题打分**——
> 搜索会围着"默认走线碰了几台设备"优化，而那个量对最终图面没有影响（实测：这一项
> 曾以 29.9 压过其余各项，把整场搜索带偏）。现在**能取到 ELK 折点就用折点**；
> 只有规格明确写了 `route`/`via` 的管线（引擎不覆盖它）才退回默认走线。
> 这条过滤规则与 `_elk_via()` **必须一致**，否则代价评估的就不是真正会画的那张图。

预估同样刻意**不带** `pipes[].via`（那是上一版走线的记忆，排版一改就成了
"接到空气里"的魔数，会让几十种排版看起来完全一样）。

### 5.6 走线：ELK 的折点就是默认走线

`chemcad_elk` 布线阶段算出的折线会随计划一起输出（`plan["elk"]["routes"]` /
`plan["pipe_via"]`），出图时作为**默认走线**用，优先级三级：

```
规格里的 route（设计者意图）  <  ELK 折点（plan["pipe_via"]）  <  迭代修正的提示
```

* `via` 会压过 `route`，所以两者不能同时留——出图侧会先剔除冲突项；
* 规格**明确写了** `route` 或 `via` 的管线**不覆盖**（那是设计者给的意图，
  例如"塔顶这根必须 VH 出"）。过滤在 `_elk_via()` 里做。

### 5.7 图幅选择

* `layout.sheet = "auto"`：逐幅面试排（A3→A0），**按最小间距**测装不装得下，
  取**最小装得下**的那张再正式排。
* 未开 auto 时，若当前幅面利用率 < `SHEET_MIN_UTIL = 38%`，只**提示**建议幅面，不擅自改图。
* 另有一道兜底：`layout.sheet=auto` 排完出图若仍 `overflow` 或压到说明框/标题栏，
  自动退到**大一号**幅面再排——排版时看不到仪器圆/引线/位号，装不装得下只能出图后实测。

> **判据变了（这是刻意的）**：旧版拿"利用率下限"当判据（无溢出 **且** 利用率 ≥ 38%）。
> ELK 版的间距是**输入参数**，分配步会主动把余量摊进间距把版面填到 `FILL_RATIO = 90%`；
> 于是"能不能填满"取决于**间距上限**而不是图纸大小——拿它当判据会把该选小图的情形
> 选成大图（实测：12 台设备的流程图会被判去用 A1）。所以现在只有一条判据：
> **装得下就用最小的那张**。利用率只用来提示"这张确实偏空"。

### 5.8 落位与钉住规则

* 设备**写了 `at`** → 视为**钉住**（作者给了坐标就是给了意图），引擎不动；
* 设备**没写 `at`** → 由计划落位（`at` 可完全省略，这是推荐用法）；
* `layout.force = true`（或 CLI `--layout-force`）→ 连钉住的一并重排；
* 混用时引擎会警告：**要么全给坐标（手工摆位）、要么全不给（引擎排版）**。

`shift_group()` 平移符号时**实体、基点、锚点三者一起挪**——漏挪锚点会出现
"设备动了、管子还接在原来那点"，而且不会报错。

## 6. ④ 三类版面缺陷：探测 → 修补 → 重建

### 6.1 三类判定口径（`chemcad_engine` 里的**结构化探测器**）

| 缺陷 | 判据 | 关键细节 |
|---|---|---|
| **符号重叠** | 两符号包围盒相交（净距 < 0）；`SYMBOL_CLEARANCE=2 mm` 内记"过近" | 设备用**本体**包围盒（EQUIP/EQUIP_IN 层），**不含接管与法兰**——接管本来就是伸出体外的短段，拿它当"设备边界"会把"离接管 1 mm"的阀门误判成压到设备上（实测：`塔↔调节阀 0.20 mm` 就是接管法兰造成的假相撞） |
| **文字压线** | 文字包围盒与线（Line/Polyline，圆按 24 边形近似）相交 | ① 文字必须有真面积（`text_rect`，含旋转）；② 文字位于某封闭框**内部**时不判它压了那个框自己的框线（说明框/标题栏里的字贴框线是正常的）；③ 图框/辅助网格/剖面线层整层跳过 |
| **管线穿设备** | 管线**让开管口之后**仍在设备本体内走超过 `PIPE_INSIDE_MIN=2 mm` | 首尾各让出 `NOZZLE_TOLERANCE=6 mm`——接管/管口本来就插进设备体内；只取 EQUIP 层的本体包围盒当"体内" |

### 6.1b 为什么 ELK 版先天地把这三类压低

`chemcad_elk` 的走线满足三条**结构性质**（回归 `[16]` 逐条钉）：

1. 每个节点在**本层内**的纵向区间互不重叠（`_enforce_separation` 兜底保证）；
   所以一条水平段沿 `y = 某节点的 y` 走，绝不会穿过同层的另一个节点。
2. 竖段一律落在**层间隙**里，而层间隙按定义不含任何节点。
3. 长边已被虚拟节点拆链，中间那几段水平线走在**虚拟节点的 y** 上，
   而虚拟节点在层里占着一格——那一格是空的。

于是"管线穿设备"**不是靠布线后处理躲开的，是版面结构排除的**。
`_avoid()` 只是**断言式**兜底：真被触发，说明上面某条假设破了。
落位阶段又有 BK 的净距约束 ⇒ 符号重叠同样先天被压低。

**但"结构上不该发生"不等于"实际没有"**：真图上还有阀门、仪表圆、回路引线、
流股数据块、说明框——它们不参与 ELK 建图，所以三类缺陷仍要**探测并迭代修正**。

### 6.2 严重级别跟着"承诺"走

```python
level = "error" if cd.meta["layout_enforced"] else "warning"
```

* **手工摆位**：记 `warning`。引擎无权替人改坐标，只提示复核。
* **`layout.mode = "auto"` 或 `layout.enforce = true`**：记 `error`。

**既然排版是引擎做的，就没有理由留下碰撞——"承诺过就要兑现"。** 这既让
"保证三类问题不再出现"有了可验收的口径，又不会让手工图突然被判死。

### 6.3 迭代修正：生成提示 → 整图重建 → 复检

三类里只有**文字挪位**能就地修（文字是叶子标注，没有别的对象引用它）；
另外两类都牵动管线重算（设备一动，用锚点解出来的管子就得重画）。所以走闭环：

```
① 排版（ELK）→ 建图 → 文字挪位 → 探测
② 有缺陷且还有预算 → 生成提示 → 回 ①
③ 只接受缺陷**更少**的方案（严格单调，不会来回震荡）
④ 收敛后输出；残留缺陷如实报出、退出码非 0（不静默）
```

轮内也做文字挪位：否则 20 多处文字压线会把收敛判据一直顶在上面，迭代永远看不到 0，
白白跑满轮数。

各修补器的"最小代价挪法"（**能滑动就不搬设备**）：

| 对象 | 挪法 | 为什么 |
|---|---|---|
| 阀门 | 改 `t` 沿管线滑一段 | 阀体离开管线就不是阀了；滑 `t` 不动拓扑，闭环也不受影响 |
| 仪表（气泡） | 沿管线**法向**让开 | 气泡是骑在管线上画的，管子在设备旁时必然相交，沿管滑动救不了；真实图纸里气泡本来就带引线挂在管侧 |
| 回路控制器 | 改 `controller_offset` | 由回路自动布置，没有管线可挂 |
| 设备 | 沿穿透最浅的一轴推开 | 牵动全局，最后一手才用 |
| 管线 | 换走线方式 / 沿冲突设备四条边绕行 | 见 §6.4 |

**候选要就地评过再选**，不能"先挪一点再看"：盲目步进会把一只阀挪到另一只阀身上，
实测出现过"挪一步 → 撞上邻居 → 再挪 → 又撞回来"的来回震荡（缺陷总数在 36~44 之间反复）。
现在直接算出**挪过去之后的包围盒**（沿管线平移 + 竖管上长宽互换），跟所有其他符号比一遍，
取"净距最大"的位置——一次到位。

同一条管线的走线决策**按管线聚合**后再定（一条线可能同时穿两台设备）。早先是
"每处冲突各自挑最优"，两次决策互相覆盖，每轮都在两个解之间跳（`pipe_through` 在 5/8 反复）。

### 6.4 接管段走线：`stub` / `stubVH` / `stubHV` / …

`ortho_path(p1,p2,"auto")` 按 `|dx|` 与 `|dy|` 的大小选先横还是先竖。从塔顶接管出发、
目标在右下方时它选**先横**——于是这条线从封头处**横着穿出塔体**。

`stub_path()` 强制两端先沿**锚点出线方向**各走一段（`NOZZLE_STUB = 9 mm`），出了设备本体再转弯。
锚点出线方向判定顺序（`anchor_direction()`）：

1. **几何**：锚点落在设备**本体**（EQUIP/EQUIP_IN，不含接管）的哪一侧；
2. **锚点名兜底**：`top/head/distillate/vapor/discharge…` → 上，`bottom/drain/liquid/skirt…` → 下，
   `left/suction/inlet/tube_in/feed…` → 左，`right/outlet/tube_out/reflux/reboiler_draw…` → 右。
   （`top` 的坐标落在接管内部，几何上判不出朝向，必须靠名字）
3. 最后退化为"离本体哪条边近就往哪边走"。

`stub*` 已列入 `repair_pipes` 的候选集，所以**哪里需要它，自动修正自己会选**——
回归 `[15]` 里有一条"降级对照"：把选中 `stub*` 的管线降级回纯正交，`pipe_through` 立刻重新出现。

### 6.5 坐标系统一（一个必须记住的坑）

`fit_to_sheet` 在**建图末尾**把整张图平移居中。而 `repair_*` 读到的是**平移后**的几何。
把平移后的绝对坐标直接写进 `pipe_via`，下一轮重建时它会被当成**平移前**的坐标用，
偏移量正好等于两次平移之差。

> 实测表现：绕行点明明算对了，重建后管线跑去了别处（`PL-RET` 的绕行点 x 一样、
> y 差了 50 mm，于是仍然穿塔）。

**规矩**：凡是要写进提示（下一轮重建时复用）的**绝对坐标**，先减掉
`chemcad_layout.unfit_shift(cd)`。增量型提示（位移量、`t`）不受影响。
ELK 的折点走的是同一个坐标系（计划坐标 = 平移前坐标），所以不受这条影响。

## 7. 规格写法

```jsonc
{
  "sheet": "A1",
  "layout": {
    "mode": "auto",            // off（默认，完全不动）| report（只诊断）| auto（排版+修正）
    "sheet": "auto",           // 或 A3/A2/A1/A0；auto = 按内容自动选幅面
    "max_per_section": 6,      // 工段上限，超了就继续对切
    "force": false,            // true = 连写了 at 的设备也重排
    "enforce": false,          // true = 即使不自动排版，三类缺陷也记 error
    "area": [16, 16, 578, 359] // 可选：直接指定排版作业区，绕过幅面推算
  },
  "equipment": [
    {"id": "T-101", "type": "tower", "tag": "T-101", "name": "脱轻塔",
     "params": {"w": 24, "h": 120, "n_tray": 8}},
    {"id": "P-101", "type": "pump", "tag": "P-101", "name": "进料泵"}
    // 不给 at —— 坐标由引擎分配
  ]
}
```

> 间距/档案/折行这些 ELK 参数**不在规格里暴露**：它们是引擎的自有旋钮，
> 由代价函数在搜索里定。规格只表达**工程意图**（分几段、要不要自动排版、
> 用哪张图幅）；把 ELK 参数摊到规格里，等于把"怎么排"的责任推给设计者。

命令行：

```bash
python scripts/draw_pfd.py spec.json --out pfd.dxf --layout auto   # 排版 + 迭代修正
python scripts/draw_pfd.py spec.json --check-only --layout report  # 只划分/统计/诊断，不动图
python scripts/draw_pfd.py spec.json --out pfd.dxf --layout auto --layout-force
python scripts/draw_pfd.py spec.json --layout-report lay.json      # 版面报告落盘
```

## 8. 三条纪律

1. **给了坐标就是钉住**。混用"给了"和"没给"会削弱版面统一性；要整体重排就加 `force`。
2. **自动排版前先查字面坐标**（`scan_literal_coords`）。`"620,430"` 这类坐标不会跟着设备走，
   结果是"线还连着、但接到空气里"。技能一贯要求用锚点或管线取点，**禁写魔数**——
   这条体检把违反项显式列出来。控制器的位置也得用引用：`controller_at` 支持引用
   （如 `"PL-FEED@0.45"`）配合 `controller_offset` 做相对偏移。
3. **残留缺陷不静默**。迭代是"只接受更优"，收敛后若仍有碰撞就如实报出、退出码非 0；
   不会为了"看起来通过"把报告写干净。

## 8.5 只出 PFD

`drawing-conventions.md` §1：**PFD = 设备 + 主物料线 + 主要参数**
（对照：P&ID = 设备 + 管道 + 阀门 + 仪表与控制回路）。
**2026-09-23 起本技能只出 PFD**，不再"一份规格出 P&ID + PFD 两张图"。

| PFD 的口径 | 做法 |
|---|---|
| 阀门 / 仪表 / 回路 / 自由信号线 | **不画**（`spec_for_type` 剪掉 `valves`/`instruments`/`loops`/`signals`） |
| 管线注记 | **流股号 + 主要参数**（不注管道号 + 管道等级） |
| 流向箭头 | **必标**（HG 20519.2；规格写 `arrows:0` 也提上来，不是 `setdefault`） |
| 标题栏 `名称` | 自动加「工艺流程图（PFD）」 |
| 说明框 | `notes_pfd` 覆盖 `notes` |

**注记只有一套**的道理：PFD 用流股号、P&ID 用管道号，是两种图各自的读图口径；
两套都注会互相压字，也违反各自的深度要求。既然只出 PFD，就是流股号这一套。

随之消失的机制：`build_both` / `build_types` / `-PFD|-PID 后缀` /
"两图同幅面、坐标逐台一致"。只有一种图型时，"两张图坐标对不上"这个问题根本不存在，
那套机制连同它的测试一起退场——留着就是死代码。
评分标准里三.1.5/3.1.6（P&ID↔PFD 一致性，0.4 分）因此**结构性不可得**，
已照实标 `out_of_scope`。

**流股数据**：

```jsonc
"streams": {
  "PL-FEED": {"no": "1", "T": "40 ℃", "P": "0.45 MPa(G)", "W": "12 500 kg/h", "phase": "液"}
}
```

也可写在单条管线上（`pipes[].stream`，优先级更高）。渲染由
`chemcad_symbols.add_stream_data()` 完成：数据块摞在管子上方（让开 6 mm）+ 一条引出线；
字段序 `no / T / P / F / W / V / phase`，自定义键排在其后。

**保证在库层，不在 CLI 层**：`draw_pfd.build_pfd(spec)` 是唯一对外入口，
`build_with_layout()` 内部也硬按 PFD 裁剪（`cur = spec_for_type(spec, resolve_drawing_type(spec))`）。
放在 CLI 里就只是个约定——谁绕过 CLI 直接调 `build()`，就可能拿到一张带阀门仪表的图。
**强制**体现在：规格里留着 `drawing_type:"pid"` 也照样出 PFD（回归里钉了这条）。

```bash
python scripts/draw_pfd.py spec.json --out sheet.dwg
#  → 只落 sheet.dwg 一张（无 -PFD / -PID 后缀；交付格式固定 DWG，经 AutoCAD COM）
```

## 9. 已知边界

**`chemcad_elk` 的实现边界**（三条，宁可写清楚也不要让人以为"ELK 都实现了"）：

1. **`NETWORK_SIMPLEX` 只实现"收窄"阶段**。完整网络单纯形要在紧致生成树上算割值
   （cut value）并做基交换；本实现做的是它的前两步——最长路给可行解、双向收窄
   把有自由度的节点收紧（`_tighten_layers`）。结果等价于"边总跨度尽可能小"，
   **不保证全局最优**。这是刻意的：化工流程图是近链状 DAG，收窄已吃掉绝大部分收益，
   而割值/基交换的实现复杂度与出错面远大于其边际收益。
2. **不做超边（hyperedge）合并布线**。ELK 会把共用源端口/目标端口的边并成超边再分开引出；
   本实现给每条边独立分配槽位，只保证**同源边的槽位相邻**（视觉上仍然成束）。
   化工图上"同一管口引两路"少见，而超边合并会让槽位分配与折点统计复杂化。
3. **只支持 `direction = RIGHT`**。其余方向传入即 `ValueError`——宁可报错，
   也不要静默按横向画出一张方向不对的图。

**版面分配本身的边界**：

* 分配只做**坐标分配**，不缩放：文字高度与线宽因此不会被破坏（`fit_to_sheet` 同此原则）。
  代价是内容可能装不进小图幅——那就换幅面，不是缩比例。
* 跨工段管线**不在 ELK 里建图**，由出图阶段的布线 + 迭代修正处理；
  所以跨段管线不会像段内管线那样享受"版面结构保证不穿设备"。
* 折行的**跨排边**走"段侧走廊"（内容最右边界 + 净距），不做更精细的走廊分配。
* 迭代上限 `MAX_LAYOUT_ROUNDS = 3`（每次整图重建）。复杂规格若 3 轮未收敛，
  输出的是"3 轮里最好的那一版"，并如实报告残留数量。
* **"丑"仍不止三类缺陷**：疏密不均、层次混乱、标注指向不明这类观感问题，
  依旧只能 `preview_dxf.py` 出图目视复核。
